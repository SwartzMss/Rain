# 7z 支持设计与回归验收

日期：2026-09-27。基线：origin/main `49a5219`（已包含 PR #196）；当前工作分支与该基线文件内容一致。
状态：首版实现已落地，正在补齐全量 CI 与上传链路验证；本文中的回归矩阵仍是发布前验收要求。

## 1. 用户行为与首期范围

上传普通 `.7z` 后自动解压，目录可展开，内部文本进入现有索引、预览、搜索、下载和删除流程。支持扩展名大小写、普通与 solid（固实）压缩、目录、空文件，以及与 ZIP/GZIP/TAR.GZ 相互嵌套；共享现有嵌套预算。

首期保证常见 COPY、LZMA、LZMA2，常见过滤器组合须通过兼容样本测试后才列为支持。其他编码明确提示不支持，不能静默漏文件。加密正文、加密文件名、分卷 `.7z.001` 和自解压 EXE 不在首期范围；识别到明确特征时提供具体提示，不要求管理员安装 7-Zip 或填写新配置。

已入库且 metadata 为 binary 的历史 7z 保持原状，不自动重新解压。需要分析内容时重新上传；验收须确认失败重试和重复上传策略不会误复用旧 binary 结果。不存在自动回填数据库的设计。

## 3. 解码库选择及实现门槛

优先验证纯 Rust 的 `sevenz-rust2`，通过 entry reader 自己控制写入。避免依赖用户机器的 7z 命令，保持 Windows / Linux 单程序部署。官方文档当前显示 0.23.0；实际版本需以原型编译、依赖审计和资源约束验证结果锁定，不直接使用未验证的 latest。

不选旧 `sevenz-rust`：上游已被标记停止维护，且有路径穿越公告。也不使用解码库直接解压到目录的便利函数，所有文件写入由 Rain 执行。

在生产接入前，原型必须确认：

1. 解析普通头、压缩头以及创建解码器时，是否能在分配前限制内存；不能等 entry callback 才检查。
2. 字典尺寸、block 数、文件数、名称总字节数及解压头大小能否检查，畸形整数计算是否受控。
3. CRC、正文加密、头加密、未知编码、特殊文件类型的可区分错误与元数据。
4. 配置最小解压 features，确认 Rust 工具链与 Windows/Linux 构建兼容。

不能实现分配前保护时，不宣称内存有硬上限；在正式支持前完成有界解析适配或选择可约束的解码实现。子进程隔离是替代方案，需要真正的 OS 内存/生命周期控制，不能仅增加异步 timeout。

## 4. 解压流程

1. 使用既有上传处理并发许可；在 blocking 工作线程解码，避免阻塞异步请求线程。
2. 校验 7z 签名，受限读取头信息；`.7z` 内容不是该格式时明确失败。
3. 解码前检查 entry 元数据、路径、特殊条目、声明尺寸和 block 资源需求。对可提前发现的问题，在产生大量临时输出前拒绝。
4. 每个归档顺序调用 entry reader；solid block 只顺序解码一次，不对每个文件调用 read_file，不把完整输出读入 Vec。
5. Rain 创建普通文件/目录，用固定缓冲区复制；每次写入前检查实际字节预算。声明值用于预检，实际输出必须验证尺寸和 CRC，不能只信文件头。
6. 失败立即中止当前归档，走既有上传失败清理；任务必须在磁盘写入结束后释放资源，避免后台解码继续写已清理目录。
7. preflight 成功后复用现有遍历及索引，最终才发布 READY；中途失败的内容不能被搜索到。

实际计数与预留只能采用一个一致策略：预检声明总量，流式按实际字节扣账；若采用预留，则流式仅核验预留余额，不能双扣。嵌套包文件及其展开内容占用的工作空间均计入 working budget，Issue 内容配额继续沿用最终非归档内容语义。

## 5. 性能与资源控制

- 上传并发仍由现有 runtime plan 管理；显式设置解码器内部线程数为 1，先避免“上传任务数 × CPU 核数”过度并行。以后依据实测优化，不新增管理员参数。
- ArchiveBudget 的工作空间限制不是解码内存限制。解码字典、压缩头、元数据和缓冲区必须单独纳入资源估算/准入；具体上限在原型测得峰值后落定，随测试记录。
- solid 包通常没有可靠的逐文件压缩尺寸；按 block 的 packed/unpacked 总量核验压缩比，结合全包工作空间上限。不能把某文件没有独立压缩尺寸当作损坏。
- 继续复用单文件、总输出、临时空间、文件数量、目录深度、路径长度和递归深度限制。它们是解压约束，与此前移除的搜索扫描量/源文件数限制无关。
- 不复用“搜索最长耗时”作为解压超时。若增加解压取消，必须能停止实际工作；spawn_blocking 的 future 超时不等于线程停止。
- 在相同机器和相同数据上比较 ZIP / 7z 普通 / 7z solid 的解压耗时、上传至 READY 耗时、峰值 RSS、临时空间峰值与并发请求延迟。不能承诺 7z 和 ZIP 同速。

## 6. 路径与错误呈现

落盘前识别 `/` 和 `\\` 分隔符、绝对路径、盘符、UNC、`..`、Windows ADS，拒绝逃逸路径；普通名称继续沿用 Rain 当前安全命名规则。该规则会改写中文等字符，不在此功能中隐式改变所有归档的命名语义。必须检测改写后重名、大小写碰撞、文件与目录冲突，不允许覆盖。

不创建 symlink、hardlink、reparse point 或特殊设备；对库无法可靠判别的特殊条目，先验证其元数据表示，不能直接恢复属性。使用独立 staging 目录并拒绝已有目标的覆盖。

建议新增可识别错误：ARCHIVE_ENCRYPTED_UNSUPPORTED、ARCHIVE_CODEC_UNSUPPORTED、ARCHIVE_INVALID、ARCHIVE_RESOURCE_LIMIT；已有空间额度错误继续复用。分卷识别明确时提示“请合并分卷或重新打包后上传”。解码器错误不能一律变成“压缩包损坏”。用户界面显示可读原因，技术细节记录日志。

## 7. 回归矩阵

| 类别 | 样本/操作 | 必须断言 |
| --- | --- | --- |
| 基础解码 | COPY、LZMA、LZMA2；solid/非 solid；空文件/目录；大写后缀 | 文件内容逐字节相等，文件数和路径正确 |
| 固实顺序 | 多个文件共用 block，后一个文件包含唯一关键字 | 不丢后续文件，不重复解码整个前缀 |
| 格式异常 | 假后缀、截断、错误 CRC、损坏头、未知 codec | 有具体失败原因，不能 READY，不能出现可搜索残留 |
| 不支持项 | 正文加密、头加密、分卷 | 可辨识时准确提示；不保存为“成功但空目录” |
| 路径 | ../、绝对路径、盘符、UNC、反斜杠、ADS、特殊条目 | 沙箱外哨兵文件不变，不产生链接或外部写入 |
| 名称碰撞 | 中文改写重名、大小写、保留名、a 文件与 a/b | 确定性失败，无覆盖 |
| 预算边界 | 每项限制恰好达到及超过 1 单位 | 边界正确、计数无重复、无整数溢出 |
| 内存攻击 | 大字典、小正文；膨胀压缩头；大量元数据 | 在危险分配前拒绝；独立进程测试自身设资源上限 |
| 嵌套 | zip→7z、7z→zip/gz/7z；超递归深度 | 成功内容可搜索；嵌套共用总预算 |
| 上传链路 | multipart 和断点续传各上传 7z | 状态最终 READY，目录、预览、搜索、下载均正确 |
| 失败恢复 | 解码中途错误、空间不足、进程重启 | 无部分索引发布，清理可恢复，后续合法上传成功 |
| 删除 | 删除解压文件、目录、跨包批量删除、删除包/Issue | 搜索结果消失，空间计数正确；hash≠id 回归保留 |
| 前端兼容 | 新 archive 节点与旧 binary 7z 节点 | 新节点可展开，旧节点仍可下载；失败文案可见 |
| 旧格式 | ZIP、TAR.GZ、TGZ、GZ 与普通日志 | 解码、嵌套、索引和失败处理保持通过 |

测试夹具固定在 backend/tests/fixtures，附生成命令、工具版本、SHA-256 和预期文件清单。至少一组由官方 7-Zip 生成，不能仅用同一个 Rust 库压缩后再解压自证兼容；常规 CI 无需安装 7-Zip。破坏性/大内存夹具使用小型构造元数据，不提交巨大压缩炸弹。

## 8. 实施顺序与发布验收

1. 原型：锁定库版本与 features，完成 solid、CRC、加密错误和分配前资源保护验证；记录内存上限依据。这是合入功能的前置条件。
2. 后端：新增解码适配，接入分类、嵌套预算和失败清理；完成单元与上传集成测试。
3. 前端：更新格式提示及节点能力测试；补上传后展开、搜索和失败提示行为测试。
4. CI：保留现有 Linux 全量检查，增加 Windows 的归档/上传/删除相关测试；验证无需外部解压软件。完整 cargo test --locked、cargo clippy --locked -- -D warnings、cargo fmt --check、前端 npm test / npm run build 均通过。
5. 性能：先记录当前 ZIP 基线，再用相同数据运行新版本；现有 ZIP 吞吐连续多次下降超过 10% 时调查，7z 重点验收资源准入与正确性，不设虚构速度承诺。
6. 发布：干净 Windows 环境测试包跑通上传→搜索→批量删除；记录峰值 RSS、时延和支持范围后再宣告支持。

当前实现已通过：7z 固实/非固实单元解压、路径穿越拒绝、后端分类测试、`cargo check --locked`。完整上传集成、Windows 测试包和性能记录仍属于合入前验收，不在本次代码改动中宣称完成。
