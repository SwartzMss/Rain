# Skill 质量评估状态反馈设计

## 背景

Skill 的 AI 质量评估可能持续较长时间。当前页面只复用全局 `busy` 状态禁用按钮，按钮文案和评分区域都没有明确说明评估正在进行，用户容易误以为操作没有生效。

## 范围

- 仅调整前端状态和展示。
- 不修改评估接口、评分规则、提示词或后端行为。
- 继续复用页面现有错误提示。

## 交互设计

页面增加独立的 `reviewingSkillId` 状态，仅覆盖质量评估请求：

- 请求开始后，评估按钮禁用并显示加载图标和 `AI 评估中...`。
- 评分区域在整个请求期间统一替换为 `正在评估，请稍候…`，不展示旧评分，也不显示“当前版本尚未评估”。
- 请求成功后重新加载 Skill 列表和详情，展示服务端返回的最新评分。
- 请求失败后清除 `reviewing`，恢复请求前已有的评分（若没有则恢复“当前版本尚未评估”），并由现有页面错误区域展示错误。

这不是评分历史功能；任一时刻只展示当前详情中的一个评分结果。

## 状态边界

- `reviewingSkillId` 与通用 `busy` 分离，避免把保存、启停等操作误标成 AI 评估。
- 评估期间所有 Skill 的评估按钮保持禁用，阻止并发或重复提交。
- 加载文案和评分占位只展示在发起评估的 Skill 上；切换到其他 Skill 后仍展示该 Skill 的正常评分内容。
- 本次改动不增加取消请求或后台任务跟踪。

## 测试

前端行为测试覆盖：

1. 首次评估期间隐藏“当前版本尚未评估”，展示加载按钮和等待提示。
2. 重新评估期间隐藏旧评分，展示等待提示。
3. 成功后退出加载状态并刷新详情。
4. 失败后退出加载状态、恢复原评分并显示现有错误提示。
