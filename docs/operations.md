# 部署与维护

[返回使用指南](../README.md) · [配置说明](configuration.md)

## 首次安装与账户

空数据库首次启动前，在程序旁的 `.env` 设置：

```dotenv
RAIN_BOOTSTRAP_ADMIN_USERNAME=admin
RAIN_BOOTSTRAP_ADMIN_PASSWORD=请替换为你自己的强密码
RESET_DB=false
```

密码为 8～128 个字符。初始化会创建唯一的活跃管理员；已有管理员时，这些变量不会重置密码或创建第二个管理员。初始化完成后可移除文件中的 bootstrap 密码，妥善保存账户凭据。

管理员通过 `/admin` 管理用户、Session、审计及系统设置；日常创建 Issue、上传和删除使用普通账户，且只能修改自己拥有的 Issue。关闭注册请使用“系统设置”；旧 `RAIN_ALLOW_REGISTRATION` 只在相应数据库配置尚未初始化时导入。

当前不支持邮箱、手机号或自助找回密码。修改 bootstrap 配置不能恢复已有账户密码；需要部署维护人员处理，避免直接手工修改密码哈希。

## 配置与数据路径

系统环境变量优先于 `.env`。程序优先加载可执行文件旁的 `.env`，找不到时通过工作目录查找配置。配置文件位置与相对数据路径的解析不是同一件事：相对路径按进程工作目录使用。建议固定启动目录，服务部署使用绝对路径，并检查启动日志中的路径。

默认路径如下：

| 内容 | 默认位置 |
| --- | --- |
| SQLite 数据库及其 WAL/SHM 配套文件 | `./data/rain.db` 及同目录配套文件 |
| 原始内容、临时工作区、搜索索引与结果 | `./data/uploads/` |
| 按 UTC 日期轮转的运行日志 | `./log/backend.log.YYYY-MM-DD` |

同一数据库只运行一个 Rain 实例，使用本地文件系统。当前部署面向可信内网 HTTP，同源提供页面及 API；`SERVER_HOST=0.0.0.0` 会监听所有网络接口，仅本机使用可改为 `127.0.0.1`。

业务容量、认证和清理策略由管理员页面维护；即时生效与待重启字段见[配置说明](configuration.md)。

## 自动清理

Issue 默认在 owner 非活跃 7 天后自动清理；管理员可以调整天数、设为 0 关闭，或维护“自动清理白名单”。

只有 owner 打开 Issue、成功上传、下载或删除文件/日志包会刷新活动时间，最多每小时一次。文件预览、搜索、上传状态轮询、临时结果生成，以及其他用户或游客的访问都不会替 owner 续期。

详细搜索预览结果默认保留 30 分钟，完整结果默认保留 7 天，读取不延长有效期。Issue 页面中的工作会话会在真实用户操作时续期；连续 3 小时没有操作会关闭该页面中此 Issue 的内部查看标签并清理搜索状态。服务端过期时间额外留出最多 4 分钟的活动同步余量。活跃工作会话关联的临时结果不会因原始 TTL 到期而被清理；会话结束或过期后，临时结果回到原 TTL 清理流程。这个会话不会续期 Issue owner 的活动时间，也不会关闭浏览器页面或删除 Issue。临时结果还受容量、记录数、请求频率和并发限制，达到上限时应等待清理或调整设置。

## 备份、升级与恢复

1. 停止 Rain，确认进程已经退出。
2. 配套备份数据库文件及仍存在的 WAL/SHM 文件、完整数据根目录和 `.env`，记录程序 `VERSION`。不要仅备份上传文件或仅复制运行中的数据库主文件。
3. 将新程序解压到独立目录，沿用已确认的配置和数据路径，不要用示例 `.env` 覆盖现有配置。
4. 启动后检查就绪状态，确认登录、Issue 列表、文件预览和搜索可用。

启动会执行数据库 migration 和兼容性校验。不兼容的历史 SQLite 搜索数据目录不会自动转为当前默认 Tantivy 数据目录；如提示需要全新目录，应先保存旧数据，再使用新的数据库和数据根目录重新上传。具体兼容性规则见[数据库说明](../doc/DB.md)。

回退时恢复升级前的整套数据和旧程序；旧程序不保证能读取升级后的 schema。`RESET_DB=true` 会删除应用 schema、migration metadata 并清空配置的数据目录，只适合可丢弃的开发测试数据，不能用于升级或故障修复。

## 故障排查

| 现象 | 检查方向 |
| --- | --- |
| `BOOTSTRAP_ADMIN_REQUIRED` | 首次管理员密码为空或格式不正确 |
| 端口绑定失败 | 检查 8078 是否已占用，修改 `SERVER_PORT` 后重启 |
| 数据库或文件访问失败 | 查看启动日志中的绝对路径，确认启动目录、磁盘空间和读写权限 |
| 上传完成但不能浏览 | 等待解压、索引和发布；失败时查看页面原因与后端日志 |
| 修改环境变量不生效 | 已初始化的业务设置以数据库为准，在管理员页面修改 |
| 分享链接无法访问 | 检查服务地址是否可达，源 Issue / 文件是否仍存在 |

存活及就绪检查：

```bash
curl http://localhost:8078/healthz
curl -i http://localhost:8078/readyz
```

`/healthz` 用于检查进程；`/readyz` 检查 SQLite 和数据目录，页面顶部展示后者。

Linux 查看运行日志：

```bash
tail -f "log/backend.log.$(date -u +%F)"
```

Windows PowerShell：

```powershell
Get-Content (Join-Path log "backend.log.$([DateTime]::UtcNow.ToString('yyyy-MM-dd'))") -Wait
```
